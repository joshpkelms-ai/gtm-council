# Play: Agentic goal run

> Brief many deep GTM tasks into a single agentic /goal-mode session, defined by a voice note that states what good looks like and how the agent will know it is done, then monitor from your phone. [[expert-eric-nowoslawski]]'s weekend motion in [[tool-codex]].

## The motion

1. **Brief by voice.** Record a voice note (Eric did 30 minutes on a dog walk) defining each task, what good looks like, and the definition of done. Codex is a good thought partner for sharpening the end state.
2. **Run from one terminal.** Kick off /goal mode and let it work through the task list; check in from your phone. A weekend of 10 in-depth tasks used ~25% of a weekly Codex allowance.
3. **Verify the end state.** The scarce human skill is writing the end state clearly enough that the agent knows when it is finished, then checking it actually hit it.

## What it can carry in one run

From Eric's example: build a new [[tool-clay]] function via the Clay CLI; a bounce-rate report; a validation-provider bake-off; a waterfalled target-market list ([[tool-prospeo]], BlitzAPI, Parallel Entity search); a 40k-company ChatGPT-ranking audit; scraping a government directory; fine-tuning a model for ICP scoring; auditing an internal list-building skill; launching campaigns for four customers.

## Discipline

- **Define done precisely** -- under-specifying the end state is the main failure mode, not token cost.
- **Checkpoint long runs** (per commenter Kyle Tusing): break the goal into steps with explicit QA criteria, continuing only when a step passes, to bound cost and avoid "wrong thing for 40 minutes" runs.
- Pair with [[concept-deterministic-first]] so the run reaches for free/cheap steps before paid ones.
