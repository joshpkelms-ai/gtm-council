# Source: Eric Nowoslawski -- 10 deep tasks from one terminal via /goal mode

> LinkedIn post by [[expert-eric-nowoslawski]]. Raw: `raw/Eric Nowoslawski/2.md`.

## Summary

Over a weekend, Eric ran 10 in-depth tasks from a single [[tool-codex]] /goal-mode chat, kicked off by a 30-minute voice note recorded on a dog walk that defined each task, what good looked like, and how the agent would know it was done. He monitored it from his phone; it used ~25% of his weekly usage. See [[play-agentic-goal-run]].

The 10 tasks included: building a new [[tool-clay]] email-finding function via the new Clay CLI (table built with his open-source `autoclay` skill); a bounce-rate report tracing bounce sources; a test of which validation provider would have caught the most "user not found" bounces (LeadMagic won); a target-market list waterfalling Prospeo, BlitzAPI, and Parallel Web Systems Entity search (see [[tool-prospeo]], [[concept-waterfall-enrichment]]); a ChatGPT search-ranking audit for 40k companies; scraping a government directory; fine-tuning the new Gemma model for custom variable writing / ICP scoring; auditing his internal company-list-building skill against three hand-made lists; and launching campaigns for four customers.

His main lesson: be even clearer about the end state, and verify it, more than you think you need to. Codex is a good thought partner for sharpening that definition of done.

## Key takeaways

- The scarce skill is writing the end state clearly enough that the agent knows when it is finished (echoed by commenters Leo Bosuener, David Turewicz, Essam Shamim).
- A voice note is now enough to brief a weekend of work that used to be a team and most of a quarter.
- Codex weekly usage is hard to exhaust even on long goal runs; cost risk is wandering off-spec, not tokens (commenter Kyle Tusing recommends checkpoints with explicit QA criteria each step).
