# Patrick Spychalski

> Co-Founder at The Kiln (a 2X Company). Tracks the agentic turn in GTM tooling: waterfall enrichment moving into [[tool-claude-code]] via [[tool-deepline]], and Clay's MCP making built workflows rep-facing.

## Who he is

Co-Founder at The Kiln, a 2X Company. Posts hands-on assessments of new GTM-engineering tooling, especially where prospecting and enrichment move into agentic CLIs.

## Core positions

- **Waterfall enrichment has arrived in Claude Code.** See [[concept-waterfall-enrichment]] and [[tool-deepline]]. [[tool-clay]] invented the data-provider waterfall; Deepline ports the concept into [[tool-claude-code]]: prompt in natural language to source companies or people, enrich (phones, emails) across providers, run agentic research via [[tool-exa]], view results in a table by session id, and write to Snowflake / Salesforce / HubSpot.
- **GTMs will work from an agentic CLI as their main hub.** Deepline's bet is that GTM engineers live in Claude Code or an equivalent, so the API should do sourcing, enrichment, and delivery for them. Credit-based pricing like Clay's.
- **Trust pre-built tables, not raw agents, for system-of-record writes.** See [[play-agentic-prospect-clay-crm-push]]. Clay's MCP is rep-facing: build a Clay function (enrich, qualify, normalise, push to CRM), expose it to the MCP, and call it from the command line. Agentically prospect, then push to a Clay table that knows your system rules.
